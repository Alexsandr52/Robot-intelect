# AEL-75: сцена G1 и коробки

## Назначение и параметры сцены

Скрипт [scripts/ael75_g1_box_scene.py](../scripts/ael75_g1_box_scene.py) создаёт одну сцену для начальной проверки контакта коробки со столом. Он использует `G1_CFG` и USD `g1_29dof_with_hand_rev_1_0.usd` из закреплённого Isaac Lab-Arena. Конфигурация задаёт 43 управляемых сустава: 29 суставов тела и 14 суставов кистей Dex3; штатные пределы суставов и PD-настройки не переопределяются.

Коробка — сплошной collision-кубоид размером **9 × 4 × 6 см**, массой **0,2 кг**. Это аппроксимация всей коробки, не модель тонких картонных стенок. Инерция однородного кубоида задаётся явно через `UsdPhysics.MassAPI`:

| Компонента | Значение |
| --- | ---: |
| `Ixx` | `8.6667e-5 kg·m²` |
| `Iyy` | `1.9500e-4 kg·m²` |
| `Izz` | `1.6167e-4 kg·m²` |

Статическое/динамическое трение коробки задано как `0.8/0.6`, стола — `0.9/0.7`; restitution равен нулю. Коэффициенты оценочные, их не измеряли на физическом объекте. Стол стоит перед роботом, его верхняя плоскость находится на высоте `0.76 м`, центр коробки — на `0.79 м`. Это начальная сцена для стоящего робота, без наклона корпуса.

## Зависимости и закрепление версий

Код сцены напрямую использует:

- Python `argparse` для параметров запуска;
- `isaaclab` — launcher, физическую конфигурацию, сцену, rigid object, контактный сенсор и вспомогательные конфиги;
- `pxr` из Isaac Sim — USD API для установки массы и диагонали инерции;
- `isaaclab_arena` — конфигурацию G1 и путь к робо-ассету.

Isaac Sim поставляет Kit, USD, PhysX и графический интерфейс, которые запускает Isaac Lab. Arena содержит конфигурацию робота и его ассет; Isaac Lab предоставляет API симуляции и интеграцию с симулятором. Это не отдельные Python-окружения: скрипт должен запускаться внутри Arena runtime, описанного в [документации среды](environment.md).

Для этой среды зафиксированы Python `3.12.16`, Isaac Sim `6.2.0.0`, Isaac Lab `3.0.0`, Arena commit `233754e5b8ba2875f90f31e3736cb4aecd945d52` и её Isaac Lab submodule `e3f7d9ff1f5d7f8280de3ece9000b7117f66bcf4`. Пакеты Isaac Sim и Python фиксируются `pyproject.toml` и Arena `uv.lock`; снимок lock-файла с контрольной суммой хранится в [`docs/locks/arena-uv.lock`](locks/arena-uv.lock). Не подменяйте подмодуль одноимённым локальным клоном `IsaacLab/`: его ревизия отличается. Полный порядок подготовки среды и причина обновлённого lock-файла описаны в [environment.md](environment.md).

## Что делает скрипт

1. Разбирает количество шагов, частоту логов, допуск дрейфа, параметры окна контакта и параметры launcher.
2. Собирает один экземпляр G1, неподвижный стол и динамическую коробку; контактный сенсор коробки фильтрует контакт по приму стола.
3. Устанавливает коробке массу `0.2 кг` и рассчитанную инерцию, сбрасывает симуляцию и задаёт суставам G1 их стандартные позиции.
4. Выполняет по умолчанию 600 шагов с `dt = 1/120 с`, пишет нормальную силу контакта коробки со столом и в конце измеряет смещение коробки относительно начала.
5. Завершает запуск ошибкой, если число суставов или суставов кистей не совпало с ожидаемым, коробка сместилась больше чем на `5 мм` или критерий контакта не выполнен.

Критерий контакта — инженерная проверка устойчивости именно этого сценария: сила должна быть не ниже половины веса коробки (`0.2 × 9.81 × 0.5 ≈ 0.981 Н`) как минимум в 90% последних 60 отсчётов. Окно по умолчанию длится `0.5 с`. Этот порог помогает отсеять одиночный финальный импульс, но сам по себе не доказывает физическую корректность материалов или модели контакта.

## Запуск

Команды Isaac Sim/Arena выполняются в Docker-контейнере Arena. Внутри контейнера checkout Arena смонтирован в `/workspaces/isaaclab_arena`; launcher Isaac Lab находится в `submodules/IsaacLab/isaaclab.sh`. Скрипт лежит в отдельном корневом репозитории `robot-move`, поэтому его нужно передать в контейнер. Команды ниже выполняются **на хосте из корня `robot-move`**, используя уже запущенный контейнер этой копии Arena:

```bash
ROOT=$(git rev-parse --show-toplevel)
ARENA_ROOT="$ROOT/IsaacLab-Arena"
ARENA_CONTAINER=$(docker ps --filter "volume=$(git -C "$ARENA_ROOT" rev-parse --show-toplevel)" --format '{{.Names}}' | head -n 1)
test -n "$ARENA_CONTAINER" || { echo 'Не найден запущенный Arena-контейнер для этого checkout' >&2; exit 1; }
docker cp "$ROOT/scripts/ael75_g1_box_scene.py" "$ARENA_CONTAINER:/tmp/ael75_g1_box_scene.py"
docker exec "$ARENA_CONTAINER" su "$(id -un)" -c \
  'cd /workspaces/isaaclab_arena && OMNI_KIT_ACCEPT_EULA=YES ACCEPT_EULA=Y ./submodules/IsaacLab/isaaclab.sh -p /tmp/ael75_g1_box_scene.py --steps 600 --physics isaacsim_physx'
```

Если контейнер ещё не запущен, сначала проверьте доступность GPU командой `nvidia-smi`, затем из корня checkout Arena выполните `./docker/run_docker.sh` и оставьте терминал с контейнером открытым. Этот launcher создаёт/запускает Arena-контейнер и монтирует checkout в указанный выше путь; для кода сцены не нужны дополнительные mounts. После этого запустите команды копирования и симуляции из второго терминала в корне `robot-move`. Не запускайте повторно launcher для уже работающей копии.

Launcher `--headless` намеренно не передаётся: стандартный запуск может показать окно симулятора и визуализацию сенсора, если контейнер был создан с поддержкой GUI. Для безоконного запуска добавьте `--headless`. Можно переопределить `--steps`, `--contact-window-steps`, `--min-contact-fraction`, `--max-box-drift-m` и `--log-interval`. Окно должно содержать хотя бы один шаг и не превышать `--steps`; короткий прогон допустим, если окно умещается в число шагов (например, `--steps 120` с окном по умолчанию `60`). Минимальная доля контакта должна лежать в `(0, 1]`; некорректные параметры останавливают запуск с сообщением об ошибке. Не запускайте второй экземпляр контейнера, если подходящего уже работающего нет: сначала проверьте инструкцию [подготовки Arena](environment.md) и доступность ресурсов GPU. Не останавливайте чужие GPU-процессы.

## Статус проверки и следующие шаги

Статически проверены расположение скрипта и launcher, версия/ревизии в локальном описании среды, путь импорта `G1_CFG`, расчёт инерции и логика проверок скрипта. Проверка синтаксиса Python прошла; CPU-only тест критерия проверил одиночный импульс, стабильный контакт и отклонение неполного окна (`python3 -m unittest tests.test_ael75_contact_criterion`). Это не запуск симулятора.

Динамический прогон, GUI, фактические силы контакта, дрейф и доступность GPU-контейнера пока не подтверждены. По локальной проверке `docker` доступен как команда, но доступ к Docker socket завершился `permission denied`; поэтому контейнер не удалось перечислить. Сам скрипт и Arena runtime в этой проверке не запускались. Считать проверку контакта пройденной можно только после фактического прогона и сохранения его вывода.

Локальные заметки связывают проект с [Linear-проектом P-AEL-8](https://linear.app/aelxsandr/project/unitree-g1-poduyom-korobki-i-sistema-manipulyacii-886951495be0/issues), содержат [AEL-73](https://linear.app/aelxsandr/issue/AEL-73/0118-proverit-konfiguraciyu-g1-i-tekushee-sostoyanie-proekta) и указывают AEL-74 как следующий этап после AEL-73. AEL-75 — текущая сцена. Локальный план описывает далее сборку задачи подъёма и политики, согласование инференса с реальным G1, затем проверку контактов и поиск выполнимых движений ([план проекта](project.md)). Это перечень из имеющихся локальных заметок, а не подтверждённый актуальный backlog или текущие статусы Linear; их нужно сверить в Linear перед выбором следующей задачи.
