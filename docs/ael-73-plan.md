# AEL-73: небольшие проверки

[Задача в Linear](https://linear.app/aelxsandr/issue/AEL-73/0118-proverit-konfiguraciyu-g1-i-tekushee-sostoyanie-proekta) требует таблицу «реальный робот ↔ симуляция» и список отсутствующих компонентов. Результаты проверок складывать в `docs/ael-73-audit.md`. Каждая строка ниже — одна ограниченная проверка с одним записываемым результатом. Если данных нет, записать «неизвестно» и источник, который нужен для ответа.

## 1. Локальная база

| № | Проверка | Результат в аудите |
| --- | --- | --- |
| 01 | Записать коммит и версию локального Isaac Lab. | SHA и `VERSION`. |
| 02 | Записать версии Python и uv из рабочего окружения. | Две версии и команды проверки. |
| 03 | Записать установленные версии Isaac Sim и Isaac Lab. | Версии пакетов и путь окружения. |
| 04 | Проверить наличие Isaac Lab-Arena и LeRobot в окружении. | Для каждого: найден / не найден, способ проверки. |
| 05 | Проверить доступную память GPU без запуска симуляции. | Модель, общая и свободная память, дата проверки. |
| 06 | Перечислить локальные файлы сцены и их формат. | Пути к USD и другим входным файлам. |

## 2. Симуляция G1

| № | Проверка | Результат в аудите |
| --- | --- | --- |
| 07 | Определить, какой из конфигов G1 реально выбран для задачи. | Имя конфига и ссылка на место выбора; если выбора нет — «не выбран». |
| 08 | Найти USD робота, на который указывает выбранный конфиг. | Путь, доступность файла и внешние зависимости. |
| 09 | Выписать число и имена управляемых суставов тела. | Список суставов и DoF. |
| 10 | Выписать модель кистей и их суставы. | Тип кистей и список суставов каждой руки. |
| 11 | Выписать суставные лимиты и ограничения приводов. | Источник и значения или отсутствие значений. |
| 12 | Выписать действия контроллера и частоту управления. | Размерность, тип команд, частота или «не задано». |
| 13 | Выписать сенсоры и наблюдения модели. | Список доступных сигналов. |

## 3. Реальный робот и коробка

| № | Проверка | Результат в аудите |
| --- | --- | --- |
| 14 | Подтвердить вариант реального G1: 23 или 29 DoF. | Вариант и ссылка на паспорт/конфигурацию робота. |
| 15 | Подтвердить тип кисти слева и справа. | Два значения и источник. |
| 16 | Получить лимиты суставов и приводов реального робота. | Документ или пометка «нет данных». |
| 17 | Записать интерфейс управления и частоту команд реального робота. | Протокол/API, тип команды, частота и источник. |
| 18 | Записать доступные датчики реального робота. | Список сигналов и источник. |
| 19 | Измерить или получить массу и габариты коробки. | Масса, три размера, способ измерения. |
| 20 | Проверить, какие параметры коробки уже заданы в сцене. | Масса, размеры, трение или «не задано». |

## 4. Сверка и завершение

| № | Проверка | Результат в аудите |
| --- | --- | --- |
| 21 | Свести DoF и кисти в таблицу «робот ↔ симуляция». | Две строки с источниками и расхождениями. |
| 22 | Добавить в таблицу лимиты, команды и датчики. | По одной строке на параметр; неизвестное не угадывать. |
| 23 | Добавить в таблицу параметры коробки. | Строки массы, размеров и трения. |
| 24 | Выписать отсутствующие компоненты и данные. | Список пробелов с конкретным следующим способом проверки. |
| 25 | Сверить аудит с критерием готовности AEL-73. | Отметка: готово / что осталось. Только после этого переходить к AEL-74. |

Проверки 01–06 и поиск конфигов выполняются чтением файлов и метаданных. Если потребуется запуск Isaac Sim, сначала оценить доступные ресурсы общей GPU. Процессы других пользователей не останавливать без чёткого разрешения.
